# Case Studies

Casos reales donde el workspace generó valor. Son la mejor evidencia para
mostrar a stakeholders, convencer al equipo, y calibrar qué skills funcionan.

## Convención de nombres

```
NNN-<slug-corto>.md
```

Ej: `001-bug-traslado-2469285.md`, `002-migration-clientes-chubut.md`.

## Qué debe tener un case study

1. **Problema**: qué estaba pasando, qué hubiera costado resolverlo sin workspace.
2. **Workspace en acción**: qué skills/agents se usaron, en qué orden.
3. **Transcripción resumida**: highlights de la interacción con Claude (editada para legibilidad).
4. **Output**: qué se produjo (código, doc, reporte).
5. **Impacto**: tiempo ahorrado (estimado), bugs detectados, aprendizajes.
6. **Qué no funcionó**: calibración honesta. Si Claude patinó, documentarlo.
